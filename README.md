# 작은 여행책 · 여섯 도시의 작은 단서

## 공동 작업 보호 규칙

Codex와 Claude는 게임 작업 전에 [AGENTS.md](AGENTS.md), [공동 작업 보호 스킬](skills/guard-shared-game/SKILL.md), [최신 배포 기록](.collaboration/release-state.json)을 확인합니다. Claude 안내는 [CLAUDE.md](CLAUDE.md)에 연결되어 있습니다. 저장소를 최신으로 받은 뒤 적용하며, 오래된 브랜치의 덮어쓰기·검증되지 않은 배포 완료 안내를 방지합니다.


## 공용 GitHub 배포 · Codex / Claude

공동 작업의 원본은 [Choiseonkyeong/Game](https://github.com/Choiseonkyeong/Game)의 `master`이며, 게임 파일은 `dist/`입니다. 작업자는 수밍과 별도 계정일 수 있으므로 수밍의 ChatGPT 로그인이나 개인 Sites 배포 권한을 공동 작업의 전제로 삼지 않습니다.

**GitHub Pages 공용 주소(활성화·배포 성공 확인 전):** https://choiseonkyeong.github.io/Game/

자동 배포 구성은 [`.github/workflows/pages.yml`](.github/workflows/pages.yml)에 있습니다. 저장소 관리자가 [Settings → Pages](https://github.com/Choiseonkyeong/Game/settings/pages)의 **Build and deployment → Source**를 **GitHub Actions**로 한 번 선택해야 합니다. 그다음 Actions의 **Publish shared game → Run workflow**를 실행합니다. Pages가 활성화되지 않았다면 위 주소가 아직 열리지 않을 수 있으며, 접속이 검증되었다고 안내하지 않습니다.

이후 어느 작업자가 `master`의 게임 파일을 수정하든 검사가 통과하면 같은 Pages 주소로 자동 배포됩니다. 실제 배포 커밋은 주소 뒤 `build-info.json`에서 확인합니다. 동시에 서로 다른 작업을 할 때는 최신 원격 변경을 통합한 뒤 저장하며 강제 푸시로 상대 작업을 덮어쓰지 않습니다.

기존 ChatGPT Sites 주소는 설정상 공개이지만 외부 작업자의 접속 실패가 보고되어 공용 접속 보장을 철회합니다. 클로드의 URL 읽기 도구 제한과 일반 브라우저의 접속 실패는 구분해서 확인해야 합니다. 자세한 절차는 [COLLABORATION.md](COLLABORATION.md)를 읽어 주세요.


현대적인 숙소와 생활 공간에서 숨은 물건을 찾아 여행책을 완성하는 2D 상황 퍼즐. 서울 → 도쿄 → 타이베이 → 방콕 → 파리 → 리스본, 6개 배경에 5단계씩 총 30단계입니다.

## 플레이

- 기본 화면에는 아이템 아이콘, 반짝이는 점, 이름표가 표시되지 않습니다.
- 그림 속 이불·베개·가방·서랍 등을 직접 밀거나 당겨 안쪽을 확인합니다. 드래그 방향과 이동량이 부분적으로 열린 상태에 반영됩니다.
- 동작 이름, 상시 설명 말풍선, 반복 안내 팝업은 표시하지 않습니다. 메모와 힌트는 필요할 때 직접 엽니다.
- 발견한 물건을 별도로 챙겨 소지품에 넣습니다. 발견과 획득은 다릅니다.
- 소지품을 골라 그림 속 대상에 사용하거나, 두 물건을 조합합니다. 드래그도 지원합니다.
- 기본 단서는 작은 끈 끝, 주머니, 접힌 종이처럼 자연스러운 생활 흔적입니다. 요청한 두 번째 힌트부터 조사 영역을 잠시 표시합니다.
- 소리가 필수인 문제, 시간 제한, 생명 제한은 없습니다. 진행은 기기에 저장합니다.

## 코드

- `dist/adventure.js`: 30단계, 실제 배경 좌표, 숨긴 장소, 행동·조합·힌트.
- `dist/play-engine.js`: 선행 행동 검증, 아이템 소비, 이동, 저장 명령 재생.
- `dist/play.js`: 보이지 않는 조사 영역, 발견 확대 화면, 소지품과 장면 직접 조작.
- `dist/travel-art`: 현대적 6개 배경, 소품·발견 장면·8포즈 단추.
- `docs/art-direction.md`: 이미지 제작 프롬프트와 저장 경로.

빌드 없는 정적 HTML/JS. `npm test`로 전체 30단계, 숨긴 물건의 획득 조건, 조합, 저장 복구, 실제 이벤트 처리 경로를 검사합니다. UI 검사는 DOM 대역을 사용하며 실제 브라우저 화면 검사와 다릅니다. 정적 장면 합성으로 첫 방의 크기·발 위치를 확인했지만, 실제 iPhone/Android 터치 및 렌더링 검수는 별도로 필요합니다.

30개 고유 배경이 아닌 6개 공간의 30단계입니다. 확대 일러스트와 장면 전환을 사용하며 영화 수준의 연속 동작이나 모든 물건의 자유로운 물리 조작은 아닙니다. 배경은 실제 예약 가능한 장소의 재현이 아닌 창작 공간입니다.

문제 구성이 바뀌었으므로 이전 온실 V5 저장은 유지하되 새 여행 V6 진행과 합치지 않습니다.


## V6.1 — 단추가 직접 조사하는 장면

단추를 이불·베개·커튼·주머니·서랍에 끌어 놓으면 해당 장소를 조사합니다. 침대로 끌면 자동으로 잠들던 동작은 조사로 교체했습니다. 물건 가까이에 놓았을 때만 동작 안내가 나타나고, 평소에는 조사 영역을 표시하지 않습니다.

이불 접힘, 베개 들림, 주머니 뒤적임, 서랍 당김, 서울 블라인드 내림 등 장소별 짧은 모션과 열린 상태를 추가했습니다. 도시는 각각 같은 배경의 조사 후 그림을 사용하며, 조사한 부분만 합성합니다. 열린 서랍의 실제 배경 일부를 잘라 확대하고 추가 확대 버튼을 제공합니다. 발견한 물건은 열린 자리에도 작게 나타나며, 챙기면 사라집니다.

베개 아래 메모, 주머니 쪽지, 빛의 변화 등 관찰은 수첩에 남습니다. 주요 퍼즐의 물건은 기존 진행 조건을 유지합니다. 모든 소품이 필수 정답은 아니며, 주변 관찰도 탐색 방향을 알려 주는 역할을 합니다. V6 저장은 그대로 이어집니다.

동작은 별도 프레임 전환·지역별 레이어·CSS 변형·8개 단추 포즈의 조합입니다. 연속 프레임의 손 애니메이션이나 실시간 천 물리 시뮬레이션은 아닙니다. UI 이벤트/진행 검사와 정적 합성 검사를 수행했으며 실제 휴대폰 브라우저의 모션·터치 검수는 별도로 필요합니다.

## V6.2 — 설명보다 장면으로 발견하기

이불·베개·주머니·가방·종이·서랍은 포인터 이동 방향과 거리에 맞춰 조사 후 그림이 점진적으로 드러납니다. 반대 방향으로 밀면 다시 덮이며 부분 개방 위치도 저장됩니다. 취소한 제스처는 진행에 영향을 주지 않습니다. 잠긴 서랍은 이 동작으로 우회할 수 없습니다. 단추를 끌어 놓거나 키보드로 누르는 기존 조작도 유지합니다.

첫 방에는 이불 아래 번호 보관함, 베개 아래 실제 쪽지, 블라인드와 조명을 함께 이용해야 보이는 축광 숫자를 추가했습니다. 조명은 다시 켤 수 있습니다. 동작 설명과 자동 조사 팝업은 없애고 서랍 내부 확대, 직접 연 메모, 요청한 힌트만 보여 줍니다. 기존 V6 첫 장 저장은 보관함 추가 이후에도 아이템과 완료 진행을 복원합니다.

16개 자동 검사가 통과했습니다. 실제 모바일 브라우저의 터치·화면 검사는 수행하지 못했습니다. 천의 드래그는 지역별 그림의 점진적 합성이며 실시간 천 물리 시뮬레이션은 아닙니다.

## V6.3 — 원본 소재의 움직임과 연결되는 관찰

서울의 이불은 원본의 6×8 메시를 포인터 방향에 따라 변형합니다. 베개는 원본 실루엣을 들어 회전하고, 커튼은 원본 린넨 텍스처와 아래쪽 접힘을 확장합니다. 사각 영역으로 다른 방 그림을 교체하던 방식과 별도 CSS 줄무늬 커튼은 제거했습니다. 베개 아래/이불 아래/커튼 뒤 clean plate를 사용합니다. 커튼에 가려진 빛의 비율과 바닥의 그림자 영역도 연동합니다. 천 물리 엔진은 아니며, 이 세 가지 연속 소품 모션은 우선 서울 방에 적용했습니다.

첫 장의 축광 숫자는 바닥 대신 카메라 보관함에 묶인 소유표에 표시됩니다. 소유표, 베개 아래 쪽지, 액자 앞뒤, 소지품을 각각 확대할 수 있습니다. 여섯 도시의 선반 책에는 사진과 세 페이지의 연결 메모가 있으며 페이지를 넘길 수 있습니다. 서울 3단계는 서랍에서 망원경을 찾고 창가에 설치한 뒤 시야 이동과 초점으로 남산타워를 관찰해야 완성됩니다. 기존 V6.2 진행은 저장 명령을 이관합니다.

방은 한 번만 그리며 상하좌우 패닝, 상하 버튼, 전체 보기 모드를 지원합니다. 새 단추 스프라이트는 기존 정체성을 유지하되 질감/채도를 방에 맞춰 조정했습니다. ImageGen 제작 자산과 프롬프트는 `docs/art-direction.md`에 기록했습니다.

검증: 19개 자동 검사 통과, 실제 캔버스 렌더러의 여섯 중간 상태를 정적으로 합성해 확인. 실제 iPhone 터치와 브라우저 프레임 속도는 검증하지 못했습니다.


## V6.4 — 직접 탐색과 햇빛 변화

단추의 화면 표시·이동·드래그와 캐릭터 안내를 제거했습니다. 장면의 소품을 직접 조작하며 기존 저장과 30단계는 이어집니다. 서울 이불의 삼각형 메시 변형을 제거하고 같은 구도의 자연스럽게 접힌 원화를 부드럽게 합성합니다. 주변 가구를 늘이거나 천을 침대 밖으로 매달지 않습니다. 실제 천 물리 시뮬레이션은 아닙니다.

커튼을 내린 비율에 따라 원본과 확산광 원화에서 계산한 조명 보정을 적용합니다. 바닥·러그·침대에 그려진 직사광 자국 자체가 줄어듭니다. 원본 린넨 소재는 유지합니다. 19개 자동 검사와 실제 캔버스 6상태 정적 합성을 통과했습니다. 러그의 햇빛 영역 평균 밝기는 열림 175 → 절반 146 → 닫힘 116으로 감소했고, 이불 조작 중 책상 영역 픽셀 변화는 0이었습니다. 실제 휴대폰 터치와 프레임 속도는 미검증입니다.


## V6.5 — 첫 방의 연속 조작과 획득 흐름

서울 이불의 완성 그림 간 디졸브를 제거했습니다. 원본에서 분리한 앞쪽 천을 불투명 스트립으로 움직이고, 매트리스는 뒤에 고정합니다. 손을 놓은 위치가 유지되며 미세한 감쇠 반응 뒤 같은 위치에 멈춥니다. 천 물리 시뮬레이션은 아닙니다. 상자는 천 아래에 먼저 그려져 이동하는 천에 의해 실제로 가려지고 드러납니다. 베개는 아래 원화를 고정한 채 들어 회전하고, 쪽지는 베개 뒤에 놓입니다. 서랍은 앞판과 내부 트레이가 분리되어 나오며 같은 장면의 내부를 확대합니다.

아이템은 장면에서 사라진 뒤 곡선을 따라 소지품 칸으로 이동하고 착지합니다. 조합은 두 재료가 모인 뒤 결과 물건으로 이어지며, 첫 사진 촬영에는 짧은 노출 반응이 있습니다. 카메라를 챙긴 뒤 상자는 비어 있습니다. 단추 제거, 상하좌우 보기, 책/사진/쪽지 확대, 조명 단서, 기존 저장과 30단계 진행을 유지합니다.

21개 자동 검사 통과. 애니메이션을 생략하지 않는 첫 방 이벤트 검사를 추가했고, 실제 캔버스 6상태 정적 합성으로 경계를 확인했습니다. 실제 모바일 터치와 프레임 속도는 미검증입니다. 자연스러운 손맛의 최종 평가는 실제 기기 확인이 필요하며, 이 연속 천/베개/서랍 렌더링 개선은 우선 서울 방에 적용됩니다. 누적 요구사항과 변경 금지 기준은 [docs/experience-contract.md](docs/experience-contract.md)에 있습니다.

## V7.0 — 화면·조작·확대 흐름 정리

공통 화면은 작은 반투명 HUD와 소지품 도크로 정리했습니다. 빈 소지품은 화면을 덮지 않고 작은 도크로 접힙니다. 전체 보기의 여백에는 같은 방의 흐린 배경을 이어 사용합니다. 책 넘김, 사진 뒤집기, 조사 창 닫힘과 드래그 복귀에 마무리 동작을 추가했습니다. 파일별 버전 URL과 service worker의 no-store 갱신, 메뉴의 `0.7.0` 표시로 오래된 파일의 혼재를 줄입니다. 기존 기기 진행은 초기화하지 않습니다.

서울 서랍은 배경과 맞는 열린 서랍 원화를 분리해 이동시키고, 잘못된 캐리어 확대 대신 실제 서랍 내부를 위한 전용 원화를 사용합니다. 내부 엽서를 옮겨 아래 물건을 찾거나 뒤집어 필름 보관 힌트를 읽을 수 있습니다. 카메라 보관함은 세 개의 숫자 다이얼을 탭하거나 세로로 밀어 조작합니다. 베개 배경 제거 범위/실루엣을 조정하고, 이불에 곡률이 있는 말림을 적용했습니다.

포인터를 따라가는 값은 속도를 유지하는 감쇠 보간을 사용합니다. 조사 버튼은 마크업이 달라질 때만 갱신하며, 미리보기에서 저장 명령 기록을 매 프레임 복제하지 않습니다. 이 변경은 코드 경로와 정적 합성 검사를 통과했지만 실제 iPhone 프레임 속도를 측정한 것은 아닙니다.
